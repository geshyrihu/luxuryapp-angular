Introduccion institucional

Este modulo es la referencia operativa para disenar, revisar y construir pantallas ERP con una experiencia seria, clara y mantenible.

Principio base

Cada pantalla debe responder tres preguntas: que ocurre, que necesita hacer el usuario y cual es la siguiente accion segura.

Criterio de calidad
  • Consistencia antes que ornamentacion.
  • Acciones claras antes que pantallas saturadas.
  • Responsive real, no solo reduccion visual.

06

Inputs y formularios

Labels superiores, ayudas visibles, validacion concreta y grillas adaptables.

Formulario de referencia
Usar nombres cortos, auditables y faciles de buscar.
El select es preferible cuando solo hay una opcion valida.
MultiSelect solo cuando comparar opciones aporta valor.
Alinear importes a la derecha en tablas y reportes.
Fechas siempre con formato local y contexto de zona horaria.
La busqueda debe indicar que campos consulta.
Textarea para observaciones; no usarlo para capturas que requieren estructura.

08

Mobile e Ionic

El render movil debe simplificar la estructura, no esconder informacion critica.

Criterios mobile
Apilar primero Formularios pasan a una columna; secciones largas se dividen por tabs o pasos.
Acciones tactiles Botones principales full width cuando cierran una tarea; iconos con area tactil suficiente.
Tablas simplificadas Mostrar cards por registro cuando haya mas de cuatro columnas relevantes.
Ionic compatible Respetar ion-content, safe areas y evitar toolbars flotantes que tapen acciones.
