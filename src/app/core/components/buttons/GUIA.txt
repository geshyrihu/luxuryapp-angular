---

## 🎯 Principio de Diseño

| Aspecto | Web (`custom-button-*`) | Mobile (`ion-button-*`) |
|---------|-------------------------|--------------------------|
| **Base** | `BaseButton` | `BaseIonicButton` |
| **UI Library** | PrimeNG 21 | Ionic (standalone) |
| **Confirmaciones** | SweetAlert2 | IonAlert nativo |
| **Iconos** | PrimeIcons (`pi pi-*`) | Ionicons (`*-outline`) |
| **Contexto de uso** | Páginas Angular, tablas, modales PrimeNG | Páginas Ionic (`<ion-page>`) |

---

## 🧩 API Común (Inputs/Outputs)

Ambas familias comparten el mismo contrato de API:

```typescript
// Inputs comunes
disabled = input<boolean>(false)
label    = input<string>('')
mostrar  = input<boolean>(true)
color/severity = input(...)
clicked  = output<MouseEvent>()

// Inputs de confirmación (delete, confirm, send-email)
confirmHeader  = input<string>('...')
confirmMessage = input<string>('...')
confirmed      = output<void>()
```

## 🚀 Cómo Importar

### En páginas Web (Angular/PrimeNG)
```typescript
import { CustomButtonEdit, CustomButtonDelete } from '@core/components/buttons/web';
// o directamente:
import { CustomButtonEdit } from '@core/components/buttons/web/custom-button-edit';
```

### En páginas Mobile (Ionic)
```typescript
import { IonButtonEdit, IonButtonDelete } from '@core/components/buttons/mobile';
// o directamente:
import { IonButtonEdit } from '@core/components/buttons/mobile/ion-button-edit';
```

---

## 💡 Patrón de Uso en Templates

### Estrategia A — El padre decide explícitamente (recomendada)
```html
<!-- En una página Ionic -->
<ion-button-edit [label]="'Editar'" (clicked)="onEdit()" />

<!-- En una página Angular Web -->
<custom-button-edit [label]="'Editar'" (clicked)="onEdit()" />
```

### Estrategia B — Condicional por plataforma
```html
@if (platform.is('mobile')) {
  <ion-button-delete [label]="'Eliminar'" (confirmed)="onDelete()" />
} @else {
  <custom-button-delete [label]="'Eliminar'" (confirmed)="onDelete()" />
}
```

---

## ⚠️ Reglas Importantes

1. **No mezcles** `ion-button-*` en páginas Angular puras ni `custom-button-*` en páginas Ion.
2. Los `ion-button-*` requieren estar dentro de `<ion-page>` o `<ion-content>`.
3. Para `ion-button-item`, registra manualmente el icono si no es de los comunes.
4. Los archivos ORIGINALES en la raíz de `buttons/` se conservan por compatibilidad — migra los imports gradualmente.
